ArtyHill.ArtyHill — Module
ArtyHill

Hardware-in-the-Loop (HIL) and real-time embedded prototyping for Julia.

Three decoupled layers:

  1. Hardware abstraction – AbstractHILBackend with allocation-free read_sensors! / write_actuators! (pure simulation, SocketCAN, EtherCAT/SOEM).
  2. Deterministic runtime – zero-allocation ControlWorkspace, control_step!, and run_realtime_loop! (mlockall, SCHEDFIFO, CPU pinning, absolute-time `clocknanosleep`, GC pause) plus a lock-free SPSC telemetry ring.
  3. Verification & codegen – allocation proofs via the AllocCheck extension (check_step_allocs) and standalone compilation via the StaticCompiler extension (compile_controller).

ArtyHill.AbstractHILBackend — Type
AbstractHILBackend

Supertype of all hardware backends. A concrete backend B must implement

init_backend!(b::B)::Int32
read_sensors!(y::AbstractVector, b::B)::Int32     # fill y in place
write_actuators!(u::AbstractVector, b::B)::Int32  # consume u
close_backend!(b::B)::Int32

read_sensors! and write_actuators! are called from the real-time thread and must not allocate on the Julia heap (verify with check_step_allocs). All functions return HIL_OK (0) on success and a negative code on failure.

ArtyHill.CiA402Codec — Type
CiA402Codec{N}(layout; mode=:csp, position_scale=1.0, velocity_scale=1.0,
               torque_scale=1.0, auto_fault_reset=false)

Process-image codec for N CiA 402 axes, for use with EtherCATBackend(...; codec=CiA402Codec{N}(...)).

  • Commands u[k]: target of axis k in user units — position (:csp), velocity (:csv) or torque (:cst). Raw value = u[k] * scale (e.g. position_scale = encoder counts per radian; torque in ‰ of rated torque).
  • Sensors y: [pos₁, vel₁, torque₁, pos₂, …] (3 per axis) in user units; unmapped objects read as 0.
  • State machine: on every cycle the statusword is decoded and the controlword advances the drive towards Operation enabled — but only while cia402_enable!(codec, true) is set. Disabled, the drive is held in Ready to switch on (no torque). In :csp, the target follows the actual position until the axis is enabled, so enabling never causes a jump.
  • Faults: a fault on any axis clears the enable flag for all axes, so after a reset nothing re-energizes until you call cia402_enable!(codec, true) again. Request a reset with cia402_fault_reset!, or pass auto_fault_reset=true to reset automatically (enable stays cleared either way). The reset is sent as rising edges on controlword bit 7 until the drive leaves Fault.

ArtyHill.CiA402Layout — Type
CiA402Layout(; out_stride, in_stride, controlword=0, target=2, mode_of_operation=-1,
               statusword=0, position_actual=2, velocity_actual=6, torque_actual=-1)

Byte offsets of the CiA 402 objects inside one axis's slice of the output (RxPDO) and input (TxPDO) process image. Axis k starts at (k-1) * stride. Use -1 for an object that is not mapped. The defaults match a common minimal mapping: outputs 0x6040 controlword (u16), 0x607A/0x60FF/0x6071 target, inputs 0x6041 statusword (u16), 0x6064 position (i32), 0x606C velocity (i32). Check your drive's ESI / PDO assignment and adjust.

ControlWorkspace{N,M,P,T}(; x0=zeros)

ArtyHill.EtherCATBackend — Type
EtherCATBackend(iface; output_bytes, iomap_size=4096, codec=PackedFloat64Codec())

EtherCAT master using SOEM (LIBSOEM). output_bytes is the size of the output part of the process image (SOEM maps outputs first, then inputs). One control cycle is: read_sensors! receives the frame sent in the previous cycle, write_actuators! encodes commands and sends the next frame — the standard one-cycle pipeline. The expected working counter is taken from the last exchange during the transition to OPERATIONAL.

Raw-socket access requires root or CAP_NET_RAW (sudo setcap cap_net_raw+ep julia).

Float64Codec()

ArtyHill.LimitedController — Type
LimitedController(controller!, umin, umax; max_rate=Inf, dt=1.0)

Wrap any controller with actuator protection, applied after it runs:

  1. non-finite commands (NaN, ±Inf) are replaced by the previous command;
  2. each command is limited to change by at most max_rate * dt per step;
  3. each command is clamped to [umin[i], umax[i]].

umin, umax and max_rate may be scalars or length-M vectors. The previous command starts at zero clamped into the limits; call reset_limits! to change it. Allocation-free.

ArtyHill.LoopStats — Type
LoopStats

Timing statistics filled by run_realtime_loop!. wake_late is the scheduling jitter (actual wake-up minus deadline), latency the compute time of control_step!, and an overrun is a step that finished after the next deadline. abort_reason is :none for a complete run, or :overruns, :errors or :exception when the loop stopped early. Use latency_percentile for percentiles from the preallocated histograms.

NonlinearPlant(f, h, x0, Val(M))

ArtyHill.PackedFloat64Codec — Type
PackedFloat64Codec()

Default process-image codec: outputs are packed Float64s starting at the output offset, inputs are packed Float64s starting at the input offset. Real drives (CiA 402 etc.) need a custom codec implementing

encode_outputs!(iomap::Ptr{UInt8}, codec, u)
decode_inputs!(y, codec, iomap::Ptr{UInt8})

where iomap already points at the start of the output / input region.

ArtyHill.RTConfig — Type
RTConfig(; period_ns, iterations, priority=80, cpu=-1, lock_memory=true,
           disable_gc=true, strict=false, max_consecutive_overruns=0,
           max_consecutive_errors=3, hist_bucket_ns=1_000, hist_buckets=2_000)

Real-time loop settings.

  • priority: SCHED_FIFO priority 1–99; 0 keeps the default scheduler.
  • cpu: pin the loop thread to this CPU (isolate it with isolcpus=/nohz_full=); -1 = no pinning.
  • lock_memory: mlockall(MCL_CURRENT | MCL_FUTURE) to prevent page faults.
  • disable_gc: run GC.gc() once, then pause the GC for the duration of the loop.
  • strict: throw if any of the above cannot be applied instead of continuing in degraded (soft) mode.
  • max_consecutive_overruns / max_consecutive_errors: watchdog. The loop stops (and drives the safe command, if one was given) after this many overruns / non-OK steps in a row. 0 disables the check.
  • hist_bucket_ns, hist_buckets: resolution and range of the latency / jitter histograms used by latency_percentile. The last bucket collects everything above the range.

SCHED_FIFO and mlockall need root or CAP_SYS_NICE / CAP_IPC_LOCK plus a suitable ulimit -r / ulimit -l.

ArtyHill.SPSCRing — Type
SPSCRing{T}(capacity)

Lock-free single-producer / single-consumer ring buffer for isbits T. The real-time thread calls try_push! (never blocks, never allocates; returns false and counts a drop when full). A background thread calls try_pop! / drain! to move samples to disk or the network. capacity is rounded up to a power of two.

ArtyHill.SocketCANBackend — Type
SocketCANBackend(iface; tx_base_id, rx_base_id, codec=Float64Codec(), extended=false,
                 rx_count=0, canfd=false, heartbeat_id=0, heartbeat_every=100)

Raw SocketCAN backend.

Classic CAN (default): actuator u[i] is sent as one frame with id tx_base_id + i - 1; sensor y[i] is updated from any received frame with id rx_base_id + i - 1.

CAN FD (canfd=true, interface must be FD-capable): all commands go out in one 64-byte frame with id tx_base_id (8-byte slot per value, so up to 8 values, updated atomically), and sensors are read from FD frames with id rx_base_id the same way.

In both modes the last value is held when no new frame arrived, and the socket is non-blocking: read_sensors! drains at most 4 * length(y) frames per cycle so its worst-case run time stays bounded.

  • rx_count > 0 installs kernel receive filters for exactly the sensor ids, so unrelated bus traffic never reaches Julia (recommended on busy buses).
  • heartbeat_id != 0 sends a 1-byte CANopen-style heartbeat (0x05, operational) with that id every heartbeat_every cycles from heartbeat!, for drives that cut power when the master goes silent.

Bring the interface up first, e.g. sudo ip link set can0 up type can bitrate 1000000 (add dbitrate 5000000 fd on for CAN FD) or, for testing, sudo ip link add dev vcan0 type vcan && sudo ip link set vcan0 mtu 72 up.

ArtyHill.control_step! — Method
control_step!(ws, controller!, backend) -> Int32

One sense → compute → actuate cycle:

read_sensors!(ws.y_meas, backend)
controller!(ws.u_cmd, ws.x_hat, ws.y_meas)
write_actuators!(ws.u_cmd, backend)

controller! may be any callable (closure, functor). The method specializes on its concrete type, so with an allocation-free controller and backend the whole step allocates zero bytes — verify with check_step_allocs. Returns the first non-OK status, or HIL_OK.

juliac_build(file; output, kind=:lib, trim="safe", project="", bundle=nothing,

ArtyHill.run_realtime_loop! — Method
run_realtime_loop!(ws, controller!, backend, cfg::RTConfig;
                   telemetry=nothing, safe_command=nothing) -> LoopStats
run_realtime_loop!(ws, controller!, backend, period_ns, iterations; kwargs...)

Run control_step!(ws, controller!, backend) every period_ns nanoseconds for iterations cycles on the calling OS thread:

  1. mlockall memory, pin the thread to cfg.cpu, switch it to SCHED_FIFO;
  2. collect garbage once, then pause the GC;
  3. sleep with clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME) against absolute deadlines, so there is no cumulative drift;
  4. after each step call heartbeat!(backend, i) and check the watchdog limits (cfg.max_consecutive_overruns, cfg.max_consecutive_errors);
  5. on exit — normal, watchdog trip or exception — write safe_command (e.g. zero torque) if one was given, then restore scheduler, affinity, memory locking and GC state. Exceptions are rethrown after that.

telemetry may be an SPSCRing built with SPSCRing(ws, capacity); one TelemetrySample is pushed per cycle (dropped, never blocking, when full).

The backend is not initialized or closed here — call init_backend! / close_backend! around it. Run a warm-up (e.g. a few control_step! calls) first so everything is compiled before the deadlines start.

Note: with Julia's GC paused, other Julia threads must not allocate heavily during the loop. Run the loop on a dedicated thread (e.g. start Julia with --threads=2 and keep the consumer side light).

ArtyHill.verijul_backend — Function
verijul_backend(dut; inputs, outputs, clock=:clk, cycles_per_step=1,
                input_scale=1.0, output_scale=1.0, signed_outputs=true) -> AbstractHILBackend

Co-simulate RTL as the "hardware": a VeriJul.jl DUT (Verilator model) becomes a backend. Each write_actuators! converts u[k] * input_scale[k] to an integer on input port inputs[k] and clocks the design cycles_per_step times; read_sensors! reads output port outputs[k] (two's complement when signed_outputs) divided by output_scale[k]. Ports must be ≤ 64 bits. Use it to test FPGA logic (PWM generators, encoder decoders, current loops) against the Julia controller before synthesis. Requires using VeriJul.

ArtyHill.LIBSOEM — Constant
LIBSOEM

Library used for SOEM calls (default "libsoem", found via the system loader path). It is a compile-time constant so hot-path ccalls bind statically (no indirect function-pointer call, which also lets AllocCheck prove the step allocation-free). Change it with set_libsoem!, which stores a Preferences.jl setting and takes effect after restarting Julia.

Build SOEM 1.4 as a shared library: cmake -DBUILD_SHARED_LIBS=ON .. && make && sudo make install.
