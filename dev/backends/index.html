Backends

A backend implements four functions, each returning HIL_OK (0) or a negative HIL_ERR_* code. Exceptions allocate, so keep them out of the hot path:

struct MyBackend <: AbstractHILBackend ... end
ArtyHill.init_backend!(b::MyBackend)
ArtyHill.read_sensors!(y, b::MyBackend)      # fill y in place, no allocations
ArtyHill.write_actuators!(u, b::MyBackend)   # no allocations
ArtyHill.close_backend!(b::MyBackend)
ArtyHill.heartbeat!(b::MyBackend, i)         # optional, called once per cycle

Verify the hot path with check_step_allocs(ws, controller, backend) (needs using AllocCheck).

Simulation

SimulationBackend wraps an AbstractPlant: DiscreteLinearPlant for LTI models, or NonlinearPlant from your own f(x, u) / h(x), which is handy for gearbox backlash or torque ripple.

SocketCAN

SocketCANBackend talks to Linux raw CAN sockets directly through libc.

  • Classic CAN: one frame per value, consecutive ids from tx_base_id / rx_base_id.
  • CAN FD (canfd=true): all commands in one 64-byte frame, updated atomically.
  • rx_count installs kernel receive filters; heartbeat_id emits a liveness frame.
  • Payloads go through a codec (Float64Codec by default). Implement encode_can / decode_can for your drive's protocol.

EtherCAT

EtherCATBackend drives SOEM 1.4's ec_* API. Point it at your SOEM build with set_libsoem!. The default codec packs Float64s. CiA402Codec speaks the CiA 402 servo profile: it decodes the statusword, steps the drive's state machine towards Operation enabled (only after cia402_enable!), scales targets and feedback, and in CSP mode keeps the target on the actual position until the drive is enabled.

A fault on any axis latches the enable flag off. Clear it with cia402_fault_reset!, which pulses controlword bit 7 until the drive leaves Fault, then re-enable explicitly. Nothing re-energizes on its own.

Testing without hardware

test/ethercat/run.sh builds SOEM 1.4 and runs the unmodified master against test/ethercat/ecat_emu.c, a frame-level emulator of a line of CiA 402 drives, over a veth pair in an unprivileged network namespace. It covers the slave scan (SII EEPROM), FMMU/SM configuration, the transition to OP, CSP motion, faults, and a simulated cable pull.
